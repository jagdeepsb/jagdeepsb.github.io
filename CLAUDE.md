## Critical: two-branch model

This is a GitHub Pages user site built with the [al-folio](https://github.com/alshedivat/al-folio) Jekyll theme. It uses **two branches with different contents**:

- **`src`** — the Jekyll *source* (`_config.yml`, `_pages/`, `_layouts/`, `_sass/`, collections `_news/`/`_projects/`/`_listprojects/`/`_making/`, `_bibliography/`, `_data/`). **All real edits happen here.**
- **`master`** — the *compiled static HTML* that GitHub Pages serves. It is generated by `jekyll build` and overwritten on every deploy.

**The working tree is checked out on `master` by default — i.e. on the built output.** Editing the root `index.html` or the `*/index.html` files here directly will be **wiped on the next deploy**. To make a lasting change, switch to `src` (`git checkout src`), edit the Jekyll source, then deploy.

Because `master` is generated, do not hand-edit it except for emergency one-off patches, and never commit source-style changes to it.

## Deploy

Deploy compiles `src` → `master` and force-pushes `master`. Two equivalent paths:

- **All-in-one** (Linux/macOS with a working Jekyll toolchain): `./bin/deploy`
- **Split build** (per README, used because `jekyll-scholar` is not supported by GitHub Pages' native build, so the site must be built locally):
  1. `./bin/deployp1` — switch to `src`, recreate the `master` branch
  2. `bundle exec jekyll build` — build into `_site/`
  3. `./bin/deployp2` — move `_site/*` to root, force-push `master`

All deploy scripts default to `SRC_BRANCH=src` and `DEPLOY_BRANCH=master`; override with `-s`/`-d`. The deploy is destructive: it runs `find . -maxdepth 1 ... -exec rm -rf {}` (keeping only `_site`, `.git`, `.gitignore`) and `git push -f`. Commit all source changes on `src` before deploying.

## Local development (on the `src` branch)

```bash
bundle install            # one-time, installs gems from Gemfile
bundle exec jekyll serve  # live-reload server at http://localhost:4000
bundle exec jekyll build  # build static site into _site/
```

There is no test suite, linter, or CI — verification is visual via `jekyll serve`.

`jekyll-scholar` (used for the publications/bibliography from `_bibliography/papers.bib`) must be built locally; GitHub Pages will not build it server-side.

## Content model (edit on `src`)

The site is organized as al-folio **collections**, each a folder of Markdown/HTML entries with front matter, rendered into the grid/list pages:

- `_news/` — news items shown on the homepage feed
- `_projects/` and `_listprojects/` — portfolio entries (project cards with hover overlays)
- `_making/` — "things I make" entries (e.g. `led`, `origami`, `wood`)
- `_pages/` — top-level pages
- `_bibliography/papers.bib` — publications, auto-rendered via jekyll-scholar
- `_data/` — structured data (e.g. co-author links)

Theme color is set in `_sass/base.scss`. Site-wide config (title, collections, plugins) is in `_config.yml`.

Every page embeds Google Analytics (gtag, `G-2NRC8J8B9G`) in its `<head>`; this is part of the layout templates on `src`, not something to add per-page.
